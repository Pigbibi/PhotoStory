# 开源部署审计（2026-09-12）

范围：PhotoStory 的 Worker/React/Python 处理器、公开 Git 历史、部署示例、
中英文配置与隐私文档，以及现有 VPS 文件权限。基线为 `d5b60d2`。
本报告不包含凭据、私人照片、数据库导出或 OAuth 回调地址。

## 已确认并修正

1. **中：手动任务未继承总 AI 分析上限。**
   `worker/index.mjs` 的 `POST /api/jobs` 只继承审核模式，用户容易把每批数量
   当作总费用限制。新手动任务现在快照保存设置中的 `analysisLimit`，与定时任务
   使用同一服务端进度检查。客户端不能用请求字段提高已保存的限额。
   回归测试先复现缺失上限，再验证超额拒绝、精确停止和不能继续领取任务。
2. **中：发布去重不应依赖可清理的预览。**
   `worker/history.mjs` 从持久化发布记录提取来源 ID，即使临时图片过期或帖子
   在 Instagram 被删除，也继续排除。`worker/publishing.mjs` 在开始发布时
   在数据库更新中检查同来源的已发布、进行中或结果不明记录，防止并发重复。
   网站展示历史帖子数、照片数和不同来源数量，不把这些数量冒充当前在线帖子数。
   目前 PhotoStory 自身账本会直接排除已使用来源；历史手动 Instagram 帖子已接入
   限量视觉匹配建议，但只有所有者确认后才加入排除集合，不能据此认定全相册已经去重。
3. **低：隐私及部署文档与实现不一致。**
   `docs/privacy.md` 仍称无发布路由、不会自动发布、令牌不续期；已改为当前
   的显式自动模式、最终成品复核、短期图片交付、条件续期及错误提醒边界。
   中文 README 的 24 小时间隔已改为 7 天，升级说明包含全部处理器模块。
   公共 Wrangler 示例的限流命名空间改为通用示例；原值是公开应用 ID，
   并非密钥，不需要因此轮换凭据。

  文件权限和 systemd 隔离，不应在模型可读取其他项目秘密的共享用户下运行。
- `.github/workflows/ci.yml` 使用只读仓库权限及普通 pull_request 事件，未将
  生产 secrets 传入测试或构建。Actions 当前使用主版本标签；固定不可变提交
  可作为后续供应链加固，不是本轮确认的凭据泄露。

## 运行及部署边界

无需新增 OAuth scope、重注册应用或轮换未泄露的密钥。不要将 secrets 改成公开
vars，也不要把备份提交到开源仓库。R2 必须保持私有；公开交付链接仅用于已启动
的发布流程且有有效期，持有链接的人在有效期内可访问图片。

AI 分类和视觉去重均可能出错。历史匹配建议和确认覆盖未完成前，保留明确日期范围；
不要以“扫描完成”代替“所有旧帖均已对应原图”。外部删除不清除历史发布账本。
网站错误横幅是站内提醒，不是邮件、推送或离线通知。

验证：包含新功能的全量 Node 测试 153/153 通过，Python 测试 54/54 通过；新增历史记录及发布阻断
另有针对性回归测试。匿名线上访问历史、草稿与内部接口均为 401，非法交付链接为 404；
实际首页响应具有上述安全头（使用系统 TLS 校验，未绕过证书验证）。部署和真实工作流结果见 [运行记录](system-review.zh-CN.md)；本报告不以单元测试
替代 Instagram 实际发布成功。
