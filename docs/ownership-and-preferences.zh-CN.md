# 所有权与选片偏好

PhotoStory 的设计单位是“一个部署实例对应一个私人编辑工作流”。它不是托管式多人
服务，也没有跨实例共享的账号、偏好或用户档案。

## 哪些数据属于一个实例

每个 Cloudflare Worker 和 D1 数据库各自保存一套私有数据：

- 管理员允许名单与连接设置；
- OneDrive 来源引用、草稿、审核证据和发布记录；
- 定期制作设置与有限的处理器状态；
- 聚合后的所有者偏好信号。

允许登录的 GitHub 账号是该实例的管理员，不是独立租户。同一实例的两位管理员
共享草稿和偏好。不同个人或组织应使用独立部署、独立 D1、独立 OAuth 应用和独立
机器凭据。

## 偏好记录了什么

PhotoStory 只记录两类有限、聚合的信号：

| 所有者操作 | 保存的信号 | 后续用途 |
| --- | --- | --- |
| 移除一张或多张轮播照片后保存草稿 | 所有者更偏好统一视觉主题的计数 | 分组时更避免混入视觉主题不同的画面 |
| 严格 AI 审核认为某项软质量不足，但所有者仍批准 | 连贯性、构图或重复帧的分歧计数 | 严格审核在安全候选之间更谨慎地排序 |

这些信号不包含照片像素、文案、地点历史、身份信息或逐张照片的否决标签。它们只是
保存在部署实例私有 D1 中的有限计数。

## 偏好不能做什么

偏好不是模型训练，也不会发送给其他 PhotoStory 部署。它不能：

- 让私密、不确定或不安全的照片变成可用候选；
- 放宽人物、地点、隐私、批准或发布保护；
- 自动批准、自动发布，或改写已有发布记录；
- 识别人物、推断私密地点或恢复已移除照片。

所有者仍需审核每篇草稿。移除照片只是对轮播组合的反馈，不代表那张照片被永久判定为
不适合使用。

## 多人如何使用

如果几个人需要彼此独立的相册和审美偏好，应每人部署一个实例。把多个用户名填入
`ALLOWED_GITHUB_USERS` 只会授予他们共同管理员权限，不会创建独立工作空间。

若要在此基础上实现多租户，必须按租户隔离每条记录、偏好、OAuth 连接、机器凭据、
存储对象和发布身份，然后才能让互不信任的用户登录。这不在当前仓库范围内。
