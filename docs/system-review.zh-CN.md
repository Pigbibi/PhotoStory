# 架构与运行边界

本文说明当前 PhotoStory 的运行模型和部署时需要保留的边界。它不是版本历史、
上线记录或第三方渗透测试报告。

## 组件职责

| 组件 | 负责什么 | 不负责什么 |
| --- | --- | --- |
| React 网站 | 登录后的编辑、审核、设置、最终发布确认 | 保存令牌、直接读取 OneDrive、调用 AI |
| Cloudflare Worker + D1 | OAuth、会话、草稿、审批、发布状态和机器接口 | 处理整批照片或运行模型 |
| 私有 R2（可选） | 保存预览和短期发布 JPEG | 公开托管相册或原图备份 |
| VPS 读取器 | 有限目录扫描、预览处理、任务推进 | 修改或删除 OneDrive 原图 |
| 隔离 AI 运行环境 | 照片筛选、主题分组、文案和严格复核 | 获取云盘令牌、修改设置、发布 Instagram |

## 数据流

1. 管理员登录网站，连接自己的 OneDrive 并建立有限日期范围的任务。
2. VPS 用机器凭据领取一个有限步骤，从 Worker 获取短期访问所需信息。
3. 读取器只下载预览，校正方向、清除 EXIF，再交给隔离的 AI 运行环境。
4. AI 返回结构化筛选与草稿建议。Worker 只接受满足完整契约的结果。
5. 管理员审核和编辑草稿。修改任何被审核内容都会使原批准失效。
6. 手动发布必须明确确认。自动发布还需要严格审核、开启后的新草稿、有效连接和
   低频规则；外部结果不明时停止并保留记录。

## 选片与地点规则

筛选先看隐私和适宜性，再看美感与主题。自拍、摆拍、人物主体、儿童、私人室内、
文档、个人信息和不确定照片不会进入草稿。路人只能作为次要背景保留。

分组同时使用连续拍摄时间、粗略区域、画幅和主视觉场景。不同场景即使位于同一景区
也不会被要求凑成同一轮播。系统区分白天、黄金时刻、蓝调和夜景；只有所有入选照片
都有一致的高置信度公共证据时，文案才会提及城市或地标。精确 GPS 不会存储或用于
文案。

## 所有权与偏好

一个部署实例是一套共享的私人工作区，不是多租户空间。实例内管理员共享草稿、设置、
发布账本和聚合偏好；不同部署彼此隔离。移除轮播照片或推翻严格审核的软质量判断，
只会形成受限的排序信号，不能放宽安全规则或自动发布。详见
[所有权与偏好](ownership-and-preferences.zh-CN.md)。

## 运行规则

- 一个任务同一时间只允许一个有效处理器领取步骤。
- 处理器每次只处理一个有限的元数据或 AI 步骤；失败和结果不明不自动重试。
- 定期制作默认关闭。启用后，timer 只推进待处理工作；积压或失败会阻止继续领取。
- 回收站和预览清理由保留规则控制，绝不删除 OneDrive 原图。
- 发布账本独立于临时图片保留；删除 Instagram 帖子不会让系统忘记已使用来源。

## 部署前检查

1. 运行 Node 测试、Python 测试和前端构建。
2. 使用独立 OAuth 应用、数据库、机器 token 和 Cloudflare 资源。
3. 验证 Worker Secret、VPS 环境文件、R2（如使用）均不可被浏览器或 AI 账户读取。
4. 用小范围照片验证 OneDrive、AI、人工审核和手动发布；不要把单元测试当作外部
   账号或 Instagram 成功的证据。

详细的安全边界见[安全设计与部署检查](security-audit.zh-CN.md)。
