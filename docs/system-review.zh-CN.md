# PhotoStory 系统检查（2026-09-12）

## 当前架构与检查范围

检查了 GitHub 登录与账号白名单、OneDrive 授权及原图版本核对、VPS 扫描与 AI 隔离、
分组和构图、审核状态、定期制作、预览保留、原图导出、Instagram 发布状态机及设置界面。
Worker 管理授权和状态；VPS 负责耗时的选片与原图处理；AI 不直接持有云盘或发帖令牌。
原检查为源码、回归测试和部署核验，不是第三方渗透测试；随后进行了下述首帖真实提交验证。

## 已修正的问题

| 问题 | 影响 | 本轮处理 |
| --- | --- | --- |
| 严格 AI 审核与自动发帖没有独立配置 | 审核通过并不意味着关闭网页后仍会发布，旧设置若被重新解释还会造成意外发帖 | 新增默认人工的发布模式，网站保存到 D1；开启时间与目标账号绑定，旧草稿不参与 |
| 成品处理依赖浏览器 | 无法无人值守完成原图裁剪与上传 | VPS 生成统一尺寸成品，检查方向、禁止放大、清除元数据，再审核实际 JPEG 并绑定摘要 |
| OneDrive 旧续期请求可覆盖新授权（已复现） | 并发重新连接后可能恢复旧账号令牌 | 精确核对旧加密记录后才能更新；冲突停止当前取图，保留新授权 |
| 旧草稿可能占满候选查询窗口 | 有足够旧草稿时，新草稿可能永远无法进入自动发布 | 数据库先筛选启用后的 AI 批准记录，再限制候选数量 |

## 采用的方案与修改范围

复用已有的 `publications` 状态机和短期 JPEG 存储，不另建发布队列或引入生产依赖。
新增 `worker/automatic-publishing.mjs` 和 `scripts/auto_publish.py`，在原有定时器中
逐步推进发布；修改设置、发布守卫、授权续期及 13 种语言文案。没有数据库迁移。
不把原有 `strict_auto` 审核设置直接改成发帖授权；不允许失败后重置发布状态盲目重试。

## 验证过的保护

- 未授权请求无法读写设置；同源和版本检查保留。
- 默认人工发布；自动发布必须另行开启且 Instagram 已连接。
- 人工批准、旧草稿、编辑后的草稿和留白布局不进入自动队列。
- 每张 9/10 与整篇复核继续生效；原图成品另行复核。
- 原图仍在 OneDrive，只读访问；版本变化、格式或大小异常均停止。
- 成品摘要不匹配或任一复核条件失败，不能开始自动发布。
- 复核拒绝会退回人工；并发处理器最多领取一次；每 7 天最多新尝试一篇。
- 关闭模式后停止后续自动请求；已发送给 Meta 的请求不能撤回。
- 外部结果不明不自动重试；发布记录保留，过期 JPEG 单独清理。
- 人工发布、审批修改、回收站、语言目录和授权续期已有测试继续通过。

验证使用 Node 测试、Python unittest 与 Vite 构建；自动发帖流程中的 Meta 调用为模拟，
不能用测试通过代替真实账号发帖成功。部署状态和实际测试数量以本次交付记录为准。

## 仍需明确的运行限制

1. **首帖人工发布验收已完成。** 账户验证恢复后，原三张横屏照片已成功发布并在 Instagram 核对；无人值守的下一次自然周期仍待观察。
2. **AI 不能保证零漏判。** 路人作为次要背景允许；自拍、摆拍和人物主体排除，不推断人物关系。
3. **后台在线要求。** 每分钟定时器负责推进；服务中断会延迟，崩溃或结果不明需要人工核实。
   无人值守流程是尽力执行，不是精确时刻排程；当前只提供固定 7 天间隔。
4. **授权不是永久有效。** Instagram 自动续期仍需进入有效窗口且未撤销；真正到期续期尚待自然观察。
5. **长期存储仍需管理。** 待审核及已批准预览按约定长期保留，不会为了释放空间自动删掉。
   后续已接入私有 R2 图片存储，并加入本站容量和请求上限；账号整体费用仍需关注，见[存储教程](storage.zh-CN.md)。
6. **信任后台处理器。** `BATCH_TOKEN` 可提交选片和 AI 证据，须由受限 VPS 持有；它不能通过接口开启发布模式。
   不应交给浏览器、模型或放入开源仓库。
7. 前端打包存在超过 500 kB 的体积提示；不影响本轮构建，按需加载更多语言可作为后续性能优化。

## 兼容和恢复

旧配置缺少发布字段时解释为人工。开启后只处理新稿；关闭再开启不会恢复旧自动尝试。
准备中的私有草稿可切回人工并重新生成发布预览；已开始或结果不明的记录需先到 Instagram
核实，不通过删除记录恢复。部署时一起更新 Worker 与文档列出的 VPS 文件。
