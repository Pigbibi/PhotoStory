# 私有 R2 图片存储

原图继续留在 OneDrive。预览和发布 JPEG 放到独立的 R2 Standard 私有桶；D1 保留
文案、设置、审核版本、原图映射、发布记录和对象索引。迁移后不再用 D1 装图片字节。

## 开通与迁移

1. 先导出 D1 到受限的私有备份。备份包含照片及加密连接记录，不能提交到 GitHub。
2. 在 Cloudflare 账号开通 R2（若尚未开通），核对[收费规则](https://developers.cloudflare.com/r2/pricing/)。
3. 创建专用桶：`npx wrangler r2 bucket create photostory-media`。使用 Standard，
   保持公共访问关闭；不要开启 `r2.dev`、公共域名或向桶内放无关文件。
4. 现有数据库执行 `worker/storage-schema.sql`；新项目完整的 `worker/schema.sql`
   已包含这些表、索引和触发器。例如：
   `npx wrangler d1 execute photostory --remote --file worker/storage-schema.sql`。
   数据库名及本地配置路径按部署调整。
5. Wrangler 配置加入：
   ```json
   "r2_buckets": [{"binding": "MEDIA_BUCKET", "bucket_name": "photostory-media"}]
   ```
   Worker vars 设置 `MEDIA_STORAGE=r2`，防止移除绑定后新增图片静默退回 D1。
   不需要额外创建或保存 S3 密钥。
6. 构建、部署，在连接设置点击「迁移现有预览」。一次最多迁移 10 张预览和 8 张
   未过期发布图，重复至剩余预览为零。受认证保护的机器接口
   `POST /internal/storage/migrate` 提供同样的限量迁移。
7. 验证预览页和存储计数。迁移不改变草稿内容、审核状态、发布模式或 OneDrive 原图。

每张先复制、读回并核对 SHA-256，再清除内容仍匹配的 D1 旧字节。复制验证失败时
旧图片保持可用。重复已完成批次不会重复上传。D1 中空字节表示改由 R2 读取。
迁移后直接取消 R2 绑定不能恢复旧图片；需保持 R2 可读或恢复核对过的私有备份。

## 容量与请求限额

| Worker 配置项 | 默认 | 允许的最大值 |
| --- | --- | --- |
| `STORAGE_MAX_BYTES` | 8,000,000,000（8 GB） | 8,000,000,000 |
| `STORAGE_WRITE_LIMIT` | 每月 100,000 次 | 1,000,000 |
| `STORAGE_READ_LIMIT` | 每月 1,000,000 次 | 10,000,000 |

这些配置不是密钥，可在部署 vars 中调低。网页显示已用/预留字节和本站 R2 请求计数，
达到 80% 提醒。上传前以数据库原子操作预留容量，避免并发上传各自使用同一剩余额度。
达到限制后停止新工作；不会删掉待审核图片腾空间。请求预算按 UTC 自然月重新计算。
读取额度用完后也会暂时停止取图，但图片仍保留。请求计数保守包含失败尝试。

**这是本站上限，不是 Cloudflare 账号扣费上限，不能保证账单永远为零。**
其他桶、绕过本站直接操作 R2 的请求、其他 Cloudflare 服务都不包含在计数内。
需要同时关注账号账单与其他应用用量，并为共享免费额度留余量。

## 隐私、清理与中断

- 预览始终由登录后的 Worker 接口提供，不公开桶地址。Instagram 仅在开始发布后
  获取原有临时成品链接，未开始或已过期的链接不能读取。
- 待审核和已批准预览随草稿长期保留；回收站仍为 30 天；不删除 OneDrive 原图。
- 发布成品过期后由现有维护定时器清理。无引用的准备对象保留至少 24 小时，保护
  尚未提交的数据库操作。后台离线会延迟清理。
- 上传结果不明时保留预留容量，不盲目重传或自动删除。需要人工核对对象和摘要后
  处理，避免漏计实际占用或误删。删除失败则保留计数，确认 R2 删除成功后才释放容量。
- 不要手动改桶内容或配置「全部对象到期删除」，否则会绕过用量计数和长期保留规则。

未配置 R2 的旧站点仍可使用原来的 D1 模式。迁移后回滚代码时必须保留 R2 读取能力，
或先恢复私有 D1 备份，不能直接回到不认识 R2 引用的旧版本。
