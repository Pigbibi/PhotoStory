# 发布历史与防重复

登录后打开「已发布记录」。页面的两组数字含义不同：

- PhotoStory 历史：成功发布的帖子数、照片使用次数、不同 OneDrive 来源数量。
  临时成品清理或在 Instagram 删除帖子后仍保留，不等于主页当前帖子数。
- Instagram 清单：用官方接口每次读取 25 篇历史帖子，统计轮播中的每张图片；
  视频不计入照片数。继续读取直到显示「清单已读完」。再次读取会开始更新，
  之前见过但后来删除的帖子仍保留在历史记录中。

清单读取使用现有 basic 权限，仅在私有 D1 保存媒体 ID、发布日期、图片数量和
分页进度。不下载历史照片、不把它们送给 AI、不公开令牌、不发帖。失败或轮播
内容不完整时，不把结果标成完整。

PhotoStory 已发布、正在发布、结果不明记录中的来源 ID 会加入选片排除名单；
发布开始时再次检查，避免另一篇草稿重复使用。即使预览已清理，记录仍有效。
此项识别同一个 OneDrive 文件，复制成新文件后 ID 会不同。

**历史清单不等于原图匹配。** Instagram 媒体 ID 与 OneDrive 文件 ID 不同；
现在加入了限量的跨平台视觉匹配建议流程。后台每次只读取一小页旧 Instagram 图片到
VPS 内存，计算本地 `dhash-v1` 指纹后立即丢弃图片，再与当前 OneDrive 预览比较。
只保存匹配建议，不保存供应商 URL 或图片字节。匹配建议不会自动排除照片，请在「已发布记录」
中检查并确认；匹配失败或未完成时，照片仍保持可选。在历史清单和匹配没有完成前，仍建议
使用明确的未发布日期范围，不要只看统计就开启全相册自动发帖。现有连拍相似图预筛与历史
Instagram 匹配是两项不同能力。

只有私有 Instagram 历史清单显示「清单完整」后，处理器才会建立匹配建议。大账号会在每次
普通制作任务中限量推进旧图指纹，因此可能需要多个任务；媒体 URL 只会给受机器凭据保护的
处理器使用，不会显示在浏览器中。

清单接口还会返回 `instagram.matchCoverage` 和独立的 `matching` 对象。当前为 `metadata_only`：只有当 Instagram
帖子或轮播子图的媒体 ID 出现在 PhotoStory 自己的发布记录中，才标记为 `photostory_post`；
其余为 `unmatched`。`sourceMatches` 只有在所有者确认匹配建议后才会增加。这里的覆盖率指
“已确认对应 OneDrive 原图”的比例，不是已读取的帖子比例，避免把完整清单误认为历史手动
发过的照片都已安全排除。`POST /api/history/matches/confirm` 只接受机器处理器已经保存的建议。
